## 1. The flip decision (load-bearing — needs sign-off before P4 lands)

**Finding (P5, authoritative V8 / Chrome, warm, median):**

| size | frozen TS /icon | WASM /icon | ratio |
|------|-----------------|------------|-------|
| 96px | 1.27 ms | 3.85 ms | **3.0×** |
| 256px | 6.94 ms | 19.2 ms | **2.8×** |

The WASM path is **~3× slower per icon**, not faster. This is the deterministic scalar-f64 + libm core
(SIMD/FMA banned for wasm↔native bit-exactness, ADR-0019) — the slowness is *intended* and structural.

**This contradicts the original "migrate to Rust for performance" premise.** M6 is a **single-pixel-truth
cutover** (one Rust pipeline feeds both preview and native apply), *not* a speedup. The justification is
correctness/maintainability (kill the parallel TS oracle), and the 3× is offset in practice by:
- the per-source **profile cache** (RenderSession skips cold analysis on re-render — analysis is 7–18 ms/icon
  cold, so warm re-renders dominate the interactive loop),
- **latest-generation coalescing** (a slider drag no longer burns K×124 dead renders — built in P2),
- **N-worker sharding** (a 124-icon warm settings change at 96px ≈ 477 ms single-thread → ≈ **80 ms wall**
  across 6 workers, vs ≈ 26 ms for the TS path).

**Recommendation:** flip. The evidence chain for correctness is strong (three-layer byte equality: export
harness + loader test + browser E2E), and single-truth is the ADR-0019 goal. But because it walks back the
perf premise and 80 ms vs 26 ms cold first-paint is a real (if sub-perceptual) regression, **the flip is an
owner-level call**, surfaced to Boss in the milestone summary. Do not flip P4's default until that lands.

Everything else in `icon-compositor/` (`compose`, `marks`, `filters`, `profile`, `analysis`, `sampling`,

> Note: `computeHueSpread`/`monoRamp` are pure functions with their own transitive deps inside the frozen set
> (e.g. hue-spread uses raster/color helpers). Relocating them means either (a) copying the small pure
> helpers they need into `icon-wasm/`, or (b) — cleaner — computing hue-spread **in Rust** via a new
> `dm_hue_spread` export and dropping the TS `computeHueSpread` entirely. Option (b) is the ADR-0019-consistent
> single-truth move and removes the last TS pixel-math dependency from the store. **Decide at execution time**
> based on how tangled the deps are; (a) is the fast path, (b) is the correct-long-term path. `monoRamp` is a
> UI swatch helper (not on the certified render path) so a straight TS relocation is fine.

## 3. The facade rewrite (icon-renderer.ts → WASM-only)

Today `IconCompositor` has: (a) the worker pool (P2 already routes it to the WASM worker under the flag), and
(b) a **synchronous in-thread fallback** for bun tests (no `Worker`/`OffscreenCanvas`) that calls the frozen
`renderTile`/`iconProfile`/`makeRaster`. After deletion those imports are gone, so the fallback must move to
**WASM-in-main**: construct a single `WasmIconRenderer` (via `WasmIconRenderer.create()` or `.fromBytes`) and
render on the main thread. This keeps `getTile`/`seedOf`/`bakeMasterPng`/`loadSource` working under bun with
zero frozen-module imports. The public surface (`loadSource/hasSource/getTile/seedOf/bakeMasterPng/
invalidateAll/setOnReady/pendingCount`) does not change.

## 4. Execution order (each step a separate, revertable commit)

1. **Relocate exports** (`feat`): create `icon-wasm/hue-spread.ts` + `icon-wasm/mono-ramp.ts` (or the Rust
   `dm_hue_spread` export per §2 note) — additive, nothing deleted yet. Byte-check `computeHueSpread` output
   against the frozen one over the hue corpus (`bun tests/icon-parity/m5` hue gate stays green).
2. **Repoint importers** (`refactor`): change the 4 import lines in `stores/icons.ts` and
   `panels/icon-axis-options.ts` to the new homes. **This is the one step that touches panels/store — lead has
   authorized it for this mechanical move only, and only once arrow-ui has landed so there is no conflict.**
   tsc + `bun test` green.
3. **Rewrite the facade fallback** (`refactor`): `icon-renderer.ts` sync fallback → WASM-in-main; drop the
   `renderTile`/`iconProfile`/`makeRaster` imports.
4. **Delete the frozen oracle** (`chore`, **its own commit for clean revert**): remove the now-unreferenced
   `icon-compositor/*.ts` pixel modules + `render.worker.ts`. Keep `shapes.ts` (§2). Verify nothing imports
   the deleted files (`grep`), tsc + `bun test` green.
5. **Flip the default** (`feat`): remove the `useWasmRenderer` flag (or default it ON) so the pool always
   spawns the WASM worker. This is the ADR-0019 single-truth moment — do only after the §1 sign-off.

## 6. Rollback

Each step is its own commit. The risky ones — the deletion (step 4) and the default flip (step 5) — are
isolated so either reverts cleanly without unwinding the relocation. Until step 5, the frozen TS path remains
the default and the WASM path stays flag-gated, so the app is never in a half-migrated shipping state.
