# M7 — Resident Auto-Format (build plan)

**Date:** 2026-07-12
**Mode:** dev-cycle iterate · builds `dm-resident` (currently an empty crate — only
`crates/dm-resident/src/lib.rs`'s module doc comment) into the v1.0 background
auto-format feature.
**Status:** PLAN — blocked on the precondition below; awaiting owner go before build.
**Normative behaviour:** spec 07 §8-§17 (`docs/specs/07-background-resident.md`).
**Decisions:** ADR-0019 (native Rust renderer, no WebView), ADR-0020 (v1 inclusion,
incremental ledger), ADR-0021 (arrow overlay default), ADR-0022 (appearance model,
trust-first reset, consent model, resident precondition).

## 0. Precondition gate — do not start T1 until this is green

Per spec 07's Dependencies and the architect's ruling recorded in the M7 design brief
PART 2: M7 cannot build on top of Wave B gaps. `docs/plans/2026-07-12-m6-wire-host.md`
§5's Wave B extension (B6–B10) must land and pass its own verification FIRST:

- B6 `SettingsStore.icon_style_json` column (store ② of spec 07 §8) exists and is
  wired to the global-Apply path.
- B7 `FsAssetStore` (real `dm_domain::AssetStore` impl, `dm-operations`) exists and
  passes its own unit tests, including `gc(live)`.
- B8 `LookHistoryStore` (store ③ of spec 07 §8) exists, corruption-tolerant, 10-cap +
  dedup + pin rules implemented (spec 07 §17).
- B9 Source fingerprint (spec 07 §4) is implemented and distinct from the post-apply
  CAS fingerprint.
- B10 `crates/dm-windows/src/watcher.rs` is a real `notify` + `notify-debouncer-full`
  implementation, not the `Err`-returning M7 skeleton.
- B1-B5 (the base M6-WIRE icon command wiring) are also done — `TxnDriver::apply` must
  already be reachable from a real Tauri command before the resident reconciler can
  reuse it.

**Gate:** `cargo test` workspace green with B6-B10 landed, before any T-numbered task
below opens a branch.

## 1. Global constraints (apply to every task below)

- Files stay ≤500 lines; split further rather than exceed it.
- Every new `dm-windows` file is `#[cfg(windows)]`, blind-written + kept compiling via
  `cargo check -p dm-windows --target x86_64-pc-windows-msvc`, tagged
  `[WINDOWS-VERIFY]` — runtime verified only on the owner's Windows box.
- Pure orchestration logic (no COM/registry) is written to compile and unit-test on
  Mac, tagged `[MAC]`, and MUST ship with a green `cargo test` on this host — no
  "verified by compiling" claims (Boil the Lake discipline).
- `dm-resident` NEVER calls `dm-elevated`/`OverlayControl` directly except through the
  pending-privileged queue's drain step, which itself only runs when the user opens
  the window (spec 07 §14) — this is a release-gated red-line, not a style
  preference.
- Every user-facing string follows spec 07 §8.1's terminology law: 外观/外观方案/
  应用/恢复系统原始外观 — never 版本/快照/回退/时光机.
- Commits use literal pathspecs, never `git add -A`, matching the shared-worktree
  convention already used in `2026-07-12-m6-wire-host.md`.
- An independent reviewer (Codex/cross-vendor per `/multi-ai`) does a spec-then-
  quality pass on `dm-resident`'s reconciler/reset/switch-version code before
  owner/Codex acceptance — this is security/data-loss-adjacent code (irreversible
  desktop writes).

## 3. Task breakdown (vertical slices)

Each task: exact path(s), intent, what it consumes, what it produces (signature),
a verify command, and its platform tag.

### T1 — `ActivityMonitor` port trait

- **Path**: `crates/dm-domain/src/ports.rs` (append)
- **Intent**: pure trait abstracting "is the desktop currently busy under the user"
  (spec 07 §11) so `dm-resident`'s reconciler can depend on it without pulling Win32.
- **Consumes**: nothing (pure trait definition).
- **Produces**: `pub trait ActivityMonitor { fn is_desktop_busy(&self) -> PortResult<bool>; }`
- **Verify**: `cargo check -p dm-domain` (host + msvc target).
- **Tag**: `[MAC]`

### T2 — `WindowsActivityMonitor` (WinEventHook)

- **Path**: `crates/dm-windows/src/activity.rs` (NEW)
- **Intent**: implement `ActivityMonitor` via `SetWinEventHook` scoped to the desktop
  `ListView` handle (`Progman` → `SHELLDLL_DefView`/`WorkerW` → `SysListView32`,
  reusing `shell/layout.rs`'s Technique B handle-resolution chain) — judge 1
  (drag/capture events, spec 07 §11) plus judge 2 fallback (foreground window class +
  `GetLastInputInfo`).
- **Consumes**: `dm_domain::ActivityMonitor` (T1), `shell::layout` handle resolution.
- **Produces**: `pub struct WindowsActivityMonitor { .. } impl ActivityMonitor for WindowsActivityMonitor`
- **Verify**: `cargo check -p dm-windows --target x86_64-pc-windows-msvc`.
  `[WINDOWS-VERIFY]` runtime: trigger a real desktop drag, confirm the busy flag holds
  for ≥1.5s past release (spec 07 §7 activity-suppression test).
- **Tag**: `[WINDOWS-VERIFY]`

### T3 — `dm-devhost` activity fake

- **Path**: `crates/dm-devhost/src/activity.rs` (NEW, Wave-B-created crate)
- **Intent**: always-idle-by-default fake with a test-controllable busy flag, so
  `dm-resident`'s own unit tests can simulate a mid-batch drag interruption without
  Windows.
- **Consumes**: `ActivityMonitor` trait (T1).
- **Produces**: `pub struct FakeActivityMonitor { .. }` with `fn set_busy(&self, bool)`.
- **Verify**: `cargo test -p dm-devhost`.
- **Tag**: `[MAC]`

### T4 — Reconciler wiring to the real watcher (consumes Wave B's B10)

- **Path**: `crates/dm-resident/src/reconciler.rs` (NEW — see T6, this task is the
  integration seam, not the watcher body itself)
- **Intent**: confirm `watch_desktops` (Wave B B10) delivers `WatchEvent`s into the
  reconciler's pending queue; M7 does not re-implement debounce/stability-probe logic
  that already lives in the watcher.
- **Consumes**: `dm_windows::watcher::WatchEvent`, `watch_desktops`.
- **Produces**: n/a — this is a wiring checkpoint folded into T6's implementation.
- **Verify**: `[WINDOWS-VERIFY]` burst test from spec 07 §7 (temp-write→rename storm →
  exactly one format per final item), run against the real watcher.
- **Tag**: `[WINDOWS-VERIFY]` (the watcher body); the reconciler side consuming events
  is `[MAC]` over a fake event stream.

### T5 — Pending-privileged queue

- **Path**: `crates/dm-resident/src/pending_privileged.rs` (NEW)
- **Intent**: the data structure backing "待处理特权项(N)" (spec 07 §14) — holds items
  the reconciler routed away from any write path because they need elevation or live
  under `Public Desktop`/`ProgramData`.
- **Consumes**: `ItemTarget`, `ItemKind` (`dm-domain`).
- **Produces**: `pub struct PendingPrivilegedQueue { .. }` with `fn push(&mut self, ItemTarget, reason: PendingReason)`, `fn drain_for_elevation(&mut self) -> Vec<ItemTarget>`, `fn len(&self) -> usize`.
- **Verify**: `cargo test -p dm-resident` — push/drain round-trip; a `Public Desktop`
  `ItemTarget` classifies as pending, a user-desktop one does not.
- **Tag**: `[MAC]`

### T6 — Reconciler core

- **Path**: `crates/dm-resident/src/reconciler.rs` (NEW)
- **Intent**: consumes `WatchEvent` hints (T4) plus a full `DesktopScanner::scan()`
  reconcile pass; applies the spec 07 §6 exclusion set; routes elevation-needing items
  to T5's queue; for the rest, resolves style (② saved-style + `kindPolicy` +
  `typeOverrides`) → bakes via `dm-icon-core` native (`--features fast`, spec 07 §15)
  → batches into a proposal (spec 07 §2) or, once the trust tier is silent AND the
  freshness check (§2 item 8) passes, calls `TxnDriver::apply` directly. Checks
  `ActivityMonitor::is_desktop_busy` between every icon (spec 07 §11).
- **Consumes**: `WatchEvent`, `ActivityMonitor` (T1/T2/T3), `LedgerStore`,
  `SettingsStore` (② saved-style, Wave B B6), `TxnDriver::apply`,
  `PendingPrivilegedQueue` (T5), the exclusion rules (spec 07 §6).
- **Produces**: `pub struct Reconciler { .. }` with `fn reconcile(&mut self, events: Vec<WatchEvent>) -> ReconcileOutcome` where `ReconcileOutcome { proposed: Vec<ItemId>, applied: Vec<ItemId>, pending_privileged: usize, conflicts: Vec<ItemId> }`.
- **Verify**: `cargo test -p dm-resident` — the burst/self-write/conflict/
  freshness-downgrade unit tests from spec 07 §7, run over fakes.
- **Tag**: `[MAC]` (pure orchestration over ports/fakes; the platform bodies it calls
  are `[WINDOWS-VERIFY]`).

### T7 — Tray state machine

- **Path**: `crates/dm-resident/src/tray_state.rs` (NEW)
- **Intent**: the 5-state machine (OFF/WATCHING/PAUSED/WORKING/ERROR, spec 07 §12) as
  a pure transition function, decoupled from the actual `tray-icon` rendering.
- **Consumes**: `Reconciler` outcomes (T6), `ActivityMonitor` busy/idle transitions
  (T2/T3).
- **Produces**: `pub enum TrayState { Off, Watching, Paused, Working { count: u32 }, Error { reason: String } }` and `pub fn transition(current: TrayState, event: TrayEvent) -> TrayState`.
- **Verify**: `cargo test -p dm-resident` — the exhaustive transition-table test from
  spec 07 §7 (every declared transition reachable, no undeclared transition exists).
- **Tag**: `[MAC]`

### T8 — `src-tauri` tray-icon feature + AppState wiring

- **Path**: `src-tauri/Cargo.toml` (edit: `tauri` `features` gains `"tray-icon"`),
  `src-tauri/src/lib.rs` (edit: register the tray + menu from spec 07 §12, wire
  `Reconciler`/`TrayState`/`PendingPrivilegedQueue` into `AppState`, add the
  windowless-residency close handler).
- **Intent**: expose the tray menu and drive the state machine (T7) from real OS
  events; window close destroys the WebView and keeps the process resident (spec 07
  §1) instead of exiting the app.
- **Consumes**: T5-T7; the existing `AppState` cfg-selected-adapter pattern already
  used for the icon/wallpaper adapters (`2026-07-12-m6-wire-host.md` §3).
- **Produces**: a running tray icon + menu; an `on_window_event(CloseRequested)`
  handler that prevents process exit when automation is enabled.
- **Verify**: Mac-Tauri E2E — app boots, tray icon renders, closing the window does
  not exit the process, reopening the window works.
- **Tag**: `[MAC]` for the Tauri wiring itself (tray-icon renders cross-platform);
  `[WINDOWS-VERIFY]` for autostart registration + real Explorer-adjacent tray
  behaviour.

### T9 — Reset-to-original operation

- **Path**: `crates/dm-operations/src/txn/reset.rs` (NEW)
- **Intent**: `reset_to_original` per spec 07 §10 — CAS-gated per-item restore-or-skip
  walk over `ledger.all()`, journaled, followed by asset GC and (if ever enabled) one
  `OverlayControl::restore()` call; clears ② saved-style and turns off the resident
  toggle in the SAME call (spec 07 §10's reset-coupling requirement).
- **Consumes**: `LedgerStore`, `ItemStateReader`, `IconApplier`, `AssetStore`
  (Wave B B7), `SettingsStore` (Wave B B6), `OverlayControl`.
- **Produces**: `pub fn reset_to_original(reader: &dyn ItemStateReader, applier: &dyn IconApplier, assets: &dyn AssetStore, settings: &SettingsStore, overlay: Option<&dyn OverlayControl>, journal: &mut dyn JournalSink, ledger: &mut dyn LedgerStore) -> Result<ResetOutcome>` where `ResetOutcome { restored: Vec<ItemId>, skipped_user_modified: Vec<ItemId> }`.
- **Verify**: `cargo test -p dm-operations` — the reset trust-first test from spec 07
  §7 (N seeded, M externally modified → exactly N−M restore, M reported skipped, ②
  empty afterward, toggle off afterward, `OverlayControl::restore` called at most
  once).
- **Tag**: `[MAC]` (pure over `dm-domain` ports, same pattern as `TxnDriver`).

### T10 — Version-switch operation

- **Path**: `crates/dm-operations/src/txn/switch_version.rs` (NEW)
- **Intent**: `switch_to_version` per spec 07 §9 — projects a ③ look-history entry
  onto the live desktop scan and drives it through the SAME `TxnDriver::apply` entry
  point auto-format uses.
- **Consumes**: `LookHistoryStore` (Wave B B8), `DesktopScanner`, the style resolver
  (`resolve(config, kindPolicy, typeOverrides, kindBucket)`), `dm-icon-core` native
  bake, `TxnDriver::apply`.
- **Produces**: `pub fn switch_to_version(id: LookVersionId, history: &dyn LookHistoryStore, scanner: &dyn DesktopScanner, driver: &TxnDriver, journal: &mut dyn JournalSink, ledger: &mut dyn LedgerStore) -> Result<ApplyOutcome>`.
- **Verify**: `cargo test -p dm-operations` — the projection test from spec 07 §7
  (icons added/removed since the version was saved; CAS conflicts skipped identically
  to a normal apply).
- **Tag**: `[MAC]`

### T11 — Tray icon assets + theme switch

- **Path**: `src-tauri/icons/tray/` (NEW asset dir: light/dark × 16/20/24/32px) +
  theme-watch glue in `src-tauri/src/lib.rs`.
- **Intent**: Windows has no `icon_as_template` auto-inversion (spec 07 §16); ship
  explicit light/dark bitmap pairs, switched at runtime by watching
  `AppsUseLightTheme` / `WM_SETTINGCHANGE`.
- **Consumes**: none (static assets) + a theme-change signal.
- **Produces**: the tray icon asset set + a runtime theme-switch handler.
- **Verify**: `[WINDOWS-VERIFY]` — toggle Windows light/dark mode, confirm the tray
  glyph swaps without a process restart.
- **Tag**: `[WINDOWS-VERIFY]` for the registry watch; the bitmap assets themselves are
  static and reviewable on any platform.

### T12 — Privileged red-line test

- **Path**: `crates/dm-resident/src/reconciler.rs` (test module, alongside T6)
- **Intent**: the release-gating red-line test from spec 07 §7/§14 — construct a
  scenario requiring elevation (a `Public Desktop` item, or a global-overlay-adjacent
  path) inside the reconciler and assert `OverlayControl::apply`/`dm-elevated` is
  NEVER invoked from that code path, only enqueued via T5.
- **Consumes**: T5, T6.
- **Produces**: a `#[test]` asserting the invariant, wired to fail loudly (panic, not
  a silent skip) if the reconciler ever calls the elevated path directly.
- **Verify**: `cargo test -p dm-resident`.
- **Tag**: `[MAC]`

## 5. Out of scope (this plan)

- Everything Wave B owns (saved-style column, `FsAssetStore`, look-history store,
  source fingerprint, the base `TxnDriver` wiring, the watcher rewrite) — a
  precondition (§0), not part of this plan's task list.
- The global arrow-overlay UAC flow itself (ADR-0021, already built) — T9 only calls
  its existing `OverlayControl::restore()`.
- Exporting the local metrics in spec 07 §17 off-device (on-device only by design;
  exporting is a separate future decision, not implied here).
- The second-tier "pure silent" auto-format mode (spec 07 §2 item 5) — unlocked-but-
  not-default, a v1.1 candidate, not built in this plan.
- Public-desktop/machine-scope elevation UI itself beyond the pending-count line (the
  full "待处理特权项(N)" review/approve screen is a follow-up if T5's queue proves it
  is needed before v1.1).
