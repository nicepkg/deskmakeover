# Plan — M5: Rust icon core (bite-sized task plan)

Phase M5 of `docs/plans/2026-07-10-tauri-migration.md` (ADR-0019). Port the FROZEN
TypeScript icon pixel pipeline (`src/icon-compositor/*`) to `crates/dm-icon-core`
as the single pixel truth, compiled twice (native + `wasm32-unknown-unknown`).
The TS compositor is the parity oracle; the corpus lives under `testdata/icons/`
(M0b). This plan is executed module by module in the ADR port order.

## Iron rules (bit-exactness — see ADR-0019 §Engineering discipline)

- `libm` for ALL transcendentals; `f64::mul_add`/FMA BANNED; no SIMD; no rayon in
  core v1. `#![forbid(unsafe_code)]` stays in `dm-icon-core`.
- Mirror TS `Float32`/`Float64` precision field-by-field. JS numbers are `f64`;
  `Float32Array` storage is `f32`; `Uint8ClampedArray` is `u8` written through the
  matching JS rounding at every byte boundary (`js_math::js_round` for `Math.round`,
  `js_trunc` for `Math.trunc`, `clamp_byte` for `raster.ts clampByte`,
  `clamp_u8_round_half_even` only where a raw non-integer is stored into a
  `Uint8ClampedArray` slot — this codebase pre-rounds almost everywhere, so that
  path is rarely hit; audit each store).
- Known trap: JSC `Math.pow` vs `libm::pow` differ 1 ulp on 34/256 sRGB decode-LUT
  entries. Classification/branch/seed decisions MUST be exactly equal; pixel-byte
  parity is the full-corpus differential arbiter (log per-stage exceptions).
- DRY: shared pixel primitives live once. Files ≤500 lines (split modules freely).
- `dm-icon-wasm` keeps exporting the growing surface (bare `extern "C"`, no
  wasm-bindgen, driven from Bun's `WebAssembly`); wasm↔native parity is structural
  (same libm) — add the CI check per module where cheap.

## Storage model (decided)

`Raster.data` is `Vec<u8>` (straight-alpha RGBA, row-major). Every write mirrors the
exact TS rounding at that site. `Float64Array`→`Vec<f64>`, `Float32Array`→`Vec<f32>`,
`Uint8Array`→`Vec<u8>`. `Rgba` is `{r,g,b,a: u8}` (as the seed already has it).

## Scope note (decided, reported to lead)

The SVG-path-string exports in `shapes.ts` (`smoothShapePathD`, `curvedShapePathD`,
`applePathD`, `shapeOutline`) render panel-chip strings, NOT pixels, and are never
exercised by the parity corpus. They are UI-layer, out of `dm-icon-core` scope; only
the pixel-producing geometry (`shapeContains` + polygon builders) is ported.
`src/compositor/*` is the Pixi WALLPAPER compositor and stays web-only (ADR-0019).

## Differential harness (built alongside module 4)

- `tests/icon-parity/m5/dump.ts` (bun, extends the M0b oracle): dumps decoded source
  RGBA (`sources/<id>.rgba`), the resolved subject mask (`masks/<id>.gray`), the
  per-source `StageProfile` JSON, the arrow asset RGBA, per-cell records for tier-a +
  tier-b (`cells.jsonl` with resolved `config`/flags/opts + expected `lane`/`fieldLane`)
  and the expected rendered RGBA (`expected/<path>.rgba`), and the tier-c hue-spread
  entries + expected seed map (`hue-spread/<preset>.json`).
- `xtask m5-native <dir>` renders every source profile / cell / hue-spread via
  `dm-icon-core`; `xtask m5-compare <dir> [--stage profiles|masks|pixels|hue]` diffs
  byte-for-byte (pixels + masks), deep-equal (profiles JSON) and exact (lane, seeds),
  emitting a per-lane / per-stage table and a non-zero exit on any gate failure. xtask
  owns serde (core stays `libm`+std only) and maps JSON → the core `Config`.
- `tests/icon-parity/m5/run.ts` orchestrates: `cargo test` → `dump.ts` → build wasm →
  `m5-native` → `m5-native --wasm` (via a Bun wasm driver) → `m5-compare`.

`bun test` must stay 359 pass (TS frozen); `cargo test` grows. Never claim green
without reading actual output (rtk shim condenses — write to a file and grep, or read
the condensed summary line).

## Note on module ordering vs dependency
`marks.ts` imports `chamferDistance` from `filters.ts` and `filters.ts` imports
`downscale` from `sampling.ts`; `compose.ts` imports both. So the code compiles in the
order: color → shapes → raster → analysis → profile → segment → hue-spread → sampling →
`filters::{chamfer_distance,smooth_step_range}` → marks → compose wiring → filters
finishes. The plan keeps the ADR's numbered order; the harness gates the mark/filter
pixels only once those modules land (compose's early gate is the mark/filter-free subset).

## 11. dm-icon-codec — ICO assembly + size ladder + content hash (append, team-lead 2026-07-11)
Port the frozen C# icon oracle's container layer into `crates/dm-icon-codec` (a stub
today; internal structure free, ≤500 lines/file). This is the bytes the M34 transaction
driver stores as an opaque content-addressed `AssetRef` (`assets.put(hash, bytes)`).

**C# sources (frozen oracle):**
- `legacy/.../IcoWriter.cs` — the ICONDIR + per-image ICONDIRENTRY + 32-bit BGRA
  bottom-up DIB (`BITMAPINFOHEADER` with `biHeight = H*2`) + all-zero AND mask
  (`stride = ((W+31)/32)*4`). Pure little-endian integer layout, no floating point.
- `legacy/.../IconResampler.cs` + `SrgbLinear.cs` — the linear-light area-average
  downscale used to build the size ladder.
- `legacy/.../GeneratedIconStore.cs` — ladder `[256,48,32,24,20,16]`, filtered to
  `size <= source.width`, `[source]` fallback if none.
- `legacy/.../OverlayBadgeIconFactory.cs` — overlay ladder `[16,20,24,32,48,256]`;
  `CreateTransparentIco` = all-transparent frames (the ADR-0021 global overlay slot).

**Rust layout:**
- `src/ico.rs` — `write_ico(frames: &[Raster]) -> Vec<u8>` (1:1 IcoWriter port,
  little-endian writers, `dib_payload`).
- `src/ladder.rs` — `LADDER_SIZES`/`OVERLAY_SIZES` consts, `resample_ladder(&Raster)`,
  `bake_ico(&Raster)`, `transparent_ico(sizes)`. The resampler is **reused** from
  `dm_icon_core::sampling::downscale` — NO second area-average impl (DRY iron rule +
  the shared pixel primitive is `dm_icon_core::raster::Raster`, re-exported).
- `src/hash.rs` — `content_hash(&[u8]) -> String` (sha256 hex, lowercase 64-char),
  `IcoAsset { bytes, content_hash }`, `write_ico_asset` / `bake_ico`.

**Consumer scenarios served:** (a) ledger `AssetRef` content-addressing (`write_ico` +
`content_hash`); (b) transparent/refined overlay ICO, ADR-0021 (`transparent_ico`); (c)
Recycle-Bin `<asset>-empty.ico` companion — a second `bake_ico`/`write_ico` of the
empty-bin source (dm-windows `paired_empty` derives the path; the codec just makes both
ICOs and their hashes distinct).

**Parity boundary (documented, not silently picked).** The differential gold standard is
the **IcoWriter container** — deterministic integer layout, so it is gated **byte-exact**
against hand-computed C# goldens (small frames, computed from the frozen code) + a full
structural decode + the frozen C# unit-test's header assertions. The **resampler ladder
is NOT re-gated against C# bytes**: v1's single-truth-source law (ADR-0019) makes the
Rust core (= TS `sampling.ts`, already M5-certified) the shipped pixels, so the baked ICO
must match the on-screen preview. C#'s `IconResampler` uses `Math.Round` (ties-to-even)
while the core uses `js_round` (ties→+∞); mirroring C# here would make installed pixels
diverge from preview at .5-tie bytes — worse than reuse. The divergence is measured and
reported; `dotnet` is unavailable on this Mac, so the C# anchor is the spec-derived
hand-computed golden, not a live C# run.

Gate: `cargo test -p dm-icon-codec` green — byte-exact container goldens (hand-computed
from the C# code + the frozen C# header test replicated), structural decode/validate,
ladder-reuse proof (each frame == `core::downscale`), deterministic + pinned-sha256 bakes
over deterministic sources (gradient/checker/alpha-disc + the transparent overlay), and
the full/empty Recycle-Bin pair. No separate `xtask` command: the codec has no TS ICO
oracle to cross-runtime-differential against, so the whole gate is cargo-native and is
wired into `bun tests/icon-parity/m5/run.ts` (step 1 now tests `dm-icon-codec` too).
`bun test` stays 359 (TS untouched).
