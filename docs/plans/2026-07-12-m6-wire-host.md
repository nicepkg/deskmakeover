# M6-WIRE — Host command wiring (Mac-buildable, Windows-deferred)

**Date:** 2026-07-12
**Mode:** dev-cycle iterate · closes the M2 bridge-command + M4 platform-adapter wiring gap
**Status:** PLAN — awaiting owner go before build
**Owner deliverable:** after the Mac build lands, a Windows handoff doc (§8) that a
second AI reads on the owner's Win11 box to do the real COM/WIC/registry verification.

## 0. The gap (why this exists)

The shipping host is **Tauri** (the C# tree is dead `legacy/`). Under Tauri today only
`settings.*` + `shell.*` window verbs route through Rust; **every `wallpaper.*` and
`icons.*` call falls through to the browser mock — in production too** (`src/bridge/
tauri.ts` `HANDLED` set = settings+shell only; `client.ts` else-branch → `mockCall`).

Yet the platform code mostly EXISTS, blind-written + msvc-cross-checked in M3/M4:
- `dm-windows`: `WindowsWallpaper` (capture/set/restore via `IDesktopWallpaper`),
  `WindowsScanner`, `WindowsStateReader`, `WindowsIconApplier`, `WindowsOverlayControl`,
  `WindowsExplorerRefresher`, `StaExecutor`.
- `dm-operations`: the full durable txn engine (journal + driver + recovery + ledger),
  pure Rust, Mac-tested incl. the kill-point battery; drives the `dm-domain` ports.
- `dm-domain`: the icon port traits (`ItemStateReader`/`IconApplier`/`AssetStore`/
  `DesktopScanner`/`ExplorerRefresher`/`OverlayControl`).

**It is never called.** `WindowsWallpaper` has zero callers; no Tauri command exposes any
of it; `dm-contracts` carries only settings+diagnostics DTOs. The feature demos perfectly
on the mock and does **nothing** to a real desktop.

M6-WIRE = the connective layer that was M2's unfinished exit ("mock bridge rides Tauri
commands; scoped asset protocol") + M4's un-exposed adapters ("manual product complete on
the new stack"). It is NOT new product behavior — the contract is already frozen in
`src/bridge/types.ts` (BRIDGE_SCHEMA_VERSION 5) + specs 04/06 + ADR-0019/0020/0021.

## 1. Load-bearing decisions (owner sign-off)

Each carries a recommendation. Veto any and the plan adjusts before build.

| # | Decision | Ruling | Why |
|---|----------|--------|-----|
| **D1** | Wallpaper Rust scope | **RESOLVED (owner 2026-07-12): Rust does ONLY (a) get screen info (multi-monitor), (b) get/set wallpaper, (c) capture/restore snapshot. Reconcile, per-monitor draft-look persistence, getState assembly, and ALL rendering stay FRONTEND.** | Rendering was always frontend (Pixi, migration-plan "web-only"); the owner draws the line tight — Rust = thin platform I/O, zero product logic. Simpler than the retired "reconcile-in-Rust" idea and drops the WallpaperStore SQLite entirely. |
| **D2** | **Mac-Tauri** behavior for the new verbs | **Route through the real Rust command path** with `#[cfg(not(windows))]` mock adapters | Exercises + verifies the real Rust command+bridge path (screen-info/apply/restore) on Mac; only COM/WIC/registry syscalls are faked; owner sees the real path work. (Icons: same — the Rust apply/txn path.) Lighter alt (keep everything on the TS mock inside Mac-Tauri) rejected: glue bugs would surface only on Windows. |
| **D3** | How the decoded wallpaper reaches the webview (`WallpaperSourceDto.url`) | Dedicated Tauri custom protocol `dmwallpaper://<monitorId>?rev=N` → `image/png` | M2 already scoped an asset protocol; keeps big pixel buffers off the JSON bridge; per-monitor + revisioned for cache-busting |
| **D4** | Build shape | **3 waves, all delivered before owner/Codex review**: A Wallpaper · B Icons · C Handoff doc | wallpaper is the bigger unknown (least built) so it leads; icons is mostly command-exposure of built adapters; waved commits keep the adversarial review tractable |

**Owner ruling on D1 (2026-07-12), applied throughout:** "壁纸组装" is NOT rendering — rendering
(zones/clarity/baking pixels) is 100% frontend Pixi and always was; Rust never touches a
wallpaper pixel except **decoding** the desktop's current image so the compositor has a bed to
draw on. Per the ruling, even the *state assembly* + *reconcile* + *draft persistence* stay
frontend. The wallpaper bridge contract therefore SHRINKS (see §2/§3): `getState`→`getScreens`
(thin: screen info + globals, no looks); `setLook` leaves the bridge (frontend `localStorage`,
same as `bareLook`); `applyBaked`/`restore` stay (they ARE get/set wallpaper). Icons is
unaffected — its Rust apply (`.lnk`/ICO/txn/overlay, the frozen single-truth kernel) is
genuine platform work and proceeds as planned ("其他就按照你的来吧").

**Non-negotiable (not a choice, called out so it is not lost):** the **pre-first-apply
snapshot**. `wallpaper.restore('all')` and `icons.restore` both revert to the desktop's
state *before DeskMakeover first touched it*. That snapshot must be captured **before the
first apply ever runs** and persisted durably. If we wire apply without wiring
capture-before-first-apply, the first apply silently destroys the user's original desktop
with no way back. This is the single highest-severity trap in the whole feature.

## 2. Capability boundary — per bridge verb

`built` = written + unit-tested on Mac with fakes and exercised by the Mac-Tauri app.
`[WV]` = `[WINDOWS-VERIFY]`: blind-written behind `#[cfg(windows)]`, msvc-cross-checked,
runtime deferred to the Windows box (handoff doc §8).

Wallpaper (post-D1-ruling — Rust is thin platform I/O; the frontend store owns reconcile +
draft persistence + `WallpaperStateDto` assembly):

| Verb | Rust (thin — built on Mac) | Frontend (TS store) | Platform seam ([WV]) |
|------|----------------------------|---------------------|----------------------|
| `wallpaper.getScreens` (was `getState`) | enumerate topology + decode each current source → raw `screens[]` + globals (NO looks) | reconcile (`monitor-reconcile.ts`) + overlay persisted looks + assemble `WallpaperStateDto` | `MonitorTopology`: `IDesktopWallpaper::GetMonitorDevicePathAt`/`GetMonitorRECT`/`GetPosition`/`GetStatus`/`GetWallpaper`; EDID/DisplayConfig fingerprint for bounds-fallback match |
| `wallpaper.getSource` | active screen's decoded source | (compositor init) | (rides getScreens decode) |
| `wallpaper.setLook` | — (leaves the bridge) | persist per-monitor draft look in `localStorage` (like `bareLook`) | none |
| `wallpaper.applyBaked` | base64 PNG → app-data file → **capture pre-first-apply snapshot if first** → applier.set | (calls it with the baked PNG) | `WindowsWallpaper::set` (`SetWallpaper`); `capture` (`GetBackgroundColor`/`GetPosition`/`GetWallpaper` per monitor) |
| `wallpaper.restore` (`monitorId` \| `'all'`) | resolve snapshot → applier.restore | (re-fetches getScreens) | `WindowsWallpaper::restore` (`SetBackgroundColor`/`SetPosition`/`SetWallpaper`) |

Icons (unaffected by D1 — genuine Rust platform work):
| `icons.scan` | scanner.scan → classify → normalize 256px sources → `ScanResultDto` | `WindowsScanner` (`IShellFolder` enum, `IFolderView2` positions — the `shell/layout.rs` stub), source extraction |
| `icons.getState` | reader-assembled `IconsStateDto` (+ `arrowOverlay`, `activeUserProfiles`) | `WindowsStateReader`; active-profile count (`ProfileList` enum) |
| `icons.setLook` | persist config/overrides/kindPolicy/typeOverrides | none (pure persistence) |
| `icons.applyBaked{Begin,Chunk,Commit}` | buffer chunked masters → `dm-icon-codec` ICO → `TxnDriver.apply` (journal→CAS→verify→commit) | `WindowsIconApplier` (`IShellLink::SetIconLocation`+`IPersistFile::Save`, per-kind writers); `ExplorerRefresher` (`SHChangeNotify`) |
| `icons.restore` | `TxnDriver` restore to captured anchor | `WindowsIconApplier::restore` (replay original `.lnk` bytes) |
| `icons.restoreOverlay` | keep-beautify: overlay→native without undoing look | `dm-elevated RestoreOverlay` (elevated verb, exact-byte overlay restore, ADR-0021) |
| `icons.exportCompare` | render before/after compare sheet | (pure, reuses icon core) |

## 3. Architecture — crate-by-crate delta

Extends the proven ports/adapters pattern (`dm-domain` trait → `dm-operations` driver →
`dm-windows` real impl / Mac fake). No new pattern is invented.

```
dm-contracts/            + wallpaper.rs, icons.rs  — #[specta::specta] DTOs mirroring
  (only settings+diag)     types.ts; feed src/bridge/generated.ts. Bump BRIDGE schema to 5.

dm-domain/ports.rs       + MonitorTopology, WallpaperApplier, ImageDecoder trait triple
                           (icon ports already present). I/O-free, msvc-clean.

dm-operations/           + wallpaper/ (snapshot-once policy + base64→file ONLY — NO reconcile,
  (txn/ledger/settings)    NO WallpaperStore; per D1 those live in the frontend store). Icon
                           apply already = TxnDriver; add the chunk-buffer + begin/commit session.

dm-windows/              wallpaper.rs already has capture/set/restore. + topology.rs
  (cfg(windows) adapters)  (GetMonitorRECT/orientation/per-monitor source enum) + decode.rs
                           (WIC → dims + PNG bytes). All #[cfg(windows)], msvc-cross-checked.

dm-devhost/  (NEW crate) Mac #[cfg(not(windows))] fake adapters: 2-monitor topology (the
                           current mock scenarios), public/ wallpaper images + real dims,
                           in-memory apply/restore. Lets the Tauri app RUN + be E2E-tested
                           on Mac. Reuses dm-operations' FakePlatform shape for icon ports.

src-tauri/commands.rs    + wallpaper_{get_screens,get_source,apply_baked,restore} (4) +
                           icons_* (9) commands; thin — delegate to dm-operations. AppState
                           holds Arc<dyn MonitorTopology/…> chosen by cfg (dm-windows on Win,
                           dm-devhost on Mac). Register dmwallpaper:// protocol. collect_commands![].

src/stores/wallpaper.ts  gains reconcile (call monitor-reconcile.ts) + per-monitor draft-look
  + lib/monitor-reconcile  localStorage persistence + WallpaperStateDto assembly from
                           getScreens — the logic the mock's buildState() held moves here so
                           real + mock share ONE assembly path. setLook stops crossing the bridge.
src/bridge/tauri.ts      HANDLED += wallpaper.{getScreens,getSource,applyBaked,restore} +
                           icons.*; tauriCall cases → generated cmds.
src/bridge/mock-*.ts     wallpaper mock SHRINKS to getScreens (screen info only); the assembly
                           it used to do now lives in the store. Pure-browser loop still works.
```

## 4. Mockable-on-Mac vs Windows-deferred boundary

**Fully built + verified on Mac** (unit tests + the Tauri-app-on-Mac E2E): dm-contracts,
dm-domain traits, ALL dm-operations orchestration (reconcile, persist, snapshot-once,
base64→file, chunk buffering, txn wiring), dm-devhost fakes, the command layer, the bridge
repoint, generated.ts drift gate.

**Blind-written `#[cfg(windows)]`, msvc-cross-checked, runtime `[WV]`:** every dm-windows
adapter body (topology geometry, WIC decode, the already-written wallpaper COM, the icon
writers, overlay). Kept compiling via `cargo check -p dm-windows --target
x86_64-pc-windows-msvc` (zero-C-dep crates only; the workspace-wide msvc check stays blocked
by rusqlite's bundled C — runs natively in the Windows batch, per M4's ruling).

The seam is a hard trait boundary, so "swap mock → real" on Windows = flip the cfg-selected
AppState adapters; the orchestration + command + bridge layers do not change.

## 8. Windows handoff doc — spec (Wave C deliverable)

Written to `docs/references/windows-wiring-handoff/README.md`, modeled on the density of the
existing `windows-settings-rust/README.md` (evidence tiers, capability table, transaction
contract, lab matrix, confidence). Contents:

1. **What's built + Mac-verified** vs **what's `[WV]`** — the §2 table, expanded to name the
   exact Rust file + the exact Win32/WIC/COM call for each seam.
2. **Per-seam verification recipe** — for each `[WV]` adapter: the API + expected
   behavior + a concrete "run this, observe that" check + known failure modes (e.g.
   `GetMonitorRECT` on a detached monitor, WIC codec absent, `SetWallpaper` empty-path clear
   semantics, EDID fingerprint drift across dock/replug).
3. **The apply/restore transaction + crash-recovery contract** — reuse dm-operations' already
   Mac-tested kill-point battery; tell the Windows AI which kill-points to reproduce live.
4. **The data-loss trap** (§1) — how to prove capture-before-first-apply fires; a from-scratch
   VM run that applies, kills, restarts, restores, and byte-compares to the pristine desktop.
5. **Multi-monitor lab matrix** — single/dual/triple, portrait, Span, slideshow,
   unreadable-dynamic wallpaper, detach/replug, mixed-DPI, EDID fingerprint fallback.
6. **How to swap mock → real** — the cfg boundary; the cross-compile check; the schema-5
   coordination; how to run the Tauri app on Windows and diff against the Mac dev-host run.
7. **Everything the builder wants to tell the verifier** — the assumptions blind-written on
   Mac that most need a real desktop to falsify, ranked by risk.
